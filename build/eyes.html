## R-OWNER-EMOJI (2026-09-23) — supersedes the 🙈 half of R-EYE-EMOJI

**The freshness eye.** Every BUILD line, the 08:30 READY line, and the restart announcement carry the eye read from the **public** status page (fetched over the URL, never the local file — a local read could show 👀 while the owner sees a frozen page).
- **Fresh (public written time under 2 min old) → 👀** (unchanged).
- **Stale → NO emoji**; the line carries the words **`page stale since HH:MM`** instead of 🙈. A failed fetch is stale. Three stale reads in a row set `blocked` (fixing the page becomes the only work). Helper: `watchers.public_eye` / `watchers.eye_prefix` (stale prefix = `page stale since HH:MM · `).

**🙋 is the one and only owner→lead signal.** 🙋 is reserved for lines the owner must act on or paste to the lead: LEAD RULING NEEDED, NOT READY at 08:30, a needed human restart, a sign-in tap, the 06:00 login link. **No other line may start with 🙋.** Every 🙋 line ends with **exactly one** of these closers:
- `send this to the lead`
- `tap the login`
- `reply restart now`

👀 lines are never owner-actioned; if a 👀-context line ever needs the owner, it also carries 🙋 (and thus one of the three closers). Central guard: `notify.owner_signal_ok(msg)` flags a 🙋 line missing a closer (a guard, never a filter — the line still sends). Read-only line types (✅ done, ⏱ progress, beat and card lines) are unchanged.

**Remaining reconciliation (follow-up):** the many existing 🙋 call-sites (`token_ping` login link, `kite_login`, `day_report`, `alarm`, …) should each be checked to end with one of the three exact closers; the central `notify` guard surfaces any that do not.
