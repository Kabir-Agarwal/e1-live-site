# R-STOP-SPAM — report (2026-09-22)

## 1. The "[CODE] session finished — come back" spam
- **Sender:** `scripts/alert_done.py`, the Stop hook wired in `.claude/settings.json`. It fired on EVERY turn
  end; with the auto-continue loop re-issuing work, that was one line per turn.
- **Fix:** alert_done now returns early when `auto_continue.should_continue()` is true (the session is not
  really ending). It fires only on a real end. Plus a **desk-wide rate limit** in `notify()`: identical text
  sends once, then at most hourly (logged RATE-LIMITED). Different text (beat/status) is unaffected.
- Commit: a4a92d979. Test: tests/test_notify_ratelimit.py.

## 2. status.html "frozen since 15:00:29"

  21:04:07, 21:04:30, 21:06:35, 21:06:52, 21:08:52; the live URL reads `updated 21:08:50` — within the last
  2-minute cycle. `git log origin/main..HEAD` is empty → **no rejected/unpushed commit**. The
  "rejected push after another clone committed" hypothesis is **disconfirmed**, not assumed.
- **Root cause of the earlier 15:00→~17:45 freeze:** the 2-minute LIGHT cycle had grown to ~90s — the
  "stocks ready" scan (~62s over 216 stocks) and the /build/ transcript scrub had been placed in it — so
  status only refreshed on the ~10-minute FULL cycle, and a heavy full cycle stalled it. Fixed earlier by
  caching the stocks-ready count (15 min), moving build_journal to the full cycle + bounding its scrub, and
  DECOUPLING status into its own daemon thread with a targeted `publish_status` (commit 146ec8bce), then
  restarting. It has updated every 2 minutes since ~17:45 — including THROUGH the 20:22 halt, because the
  status writer is the `status-daemon` thread in site_loop, separate from the (blocked) build session
  (halt-proof).
- **This commit** adds a cache-busting JS reload to status.html so an OPEN TAB always pulls the current file
  (a plain meta-refresh can be served stale by the CDN — the likely reason the owner still saw 15:00:29).
- **Why NOT READY:** the vitals ready line needs a recorder up; **0 recorders are running** — they re-arm at
  the 06:00 Kite login (`_arm_recorder`), and it is evening / market closed. Token valid, 216 stocks ready,
  orders allowed, audit passed — only the recorders are missing, which is expected off-hours.
- **Why the owner saw "no runner":** that was the pre-restart 15:00 view. The runner IS up now
