+# Lead-on-laptop — design note (no build yet)
+
+_BACKLOG item, owner ruling R-BACKLOG (2026-09-22). A design note only: it records how the lead (the
+autonomous builder session) would run directly on this laptop, and the constraints that already bind it. No
+code is written by this note; a build is a separate, later item the owner promotes._
+
+## What "the lead on the laptop" means
+
+The **lead** is the autonomous Claude session that reads `CLAUDE.md` + `QUEUE.md`/`BACKLOG.md`, does one item
+per run under the loop protocol (§1), and chains to the next. "On the laptop" means it runs on **this**
+machine, in the foreground, started by a human — not in a cloud sandbox and not resurrected by any scheduler.
+
+That is already the standing law, and this note does not change it:
+
+- **§14.7 — restart is a human act.** No logon task, no scheduled task, no supervisor that brings the runner
+  back. `START_CHAIN.bat` in the repo root is the only way the chain starts, and a human double-clicks it.
+  _Why: a runner that resurrects itself is a runner nobody can be sure is stopped (the ghost-runner lesson)._
+- **§14.10 — the live python stack is human-only.** Only the owner's two double-click files
+  (`START_E1_STACK.bat` / `STOP_E1_STACK.bat`) start or stop the trading stack; the lead prepares them and
+  tells the owner, and never relaunches the stack itself.
+- **`CHAIN_STOP` is the kill switch** and now has nothing racing it (§14.7 reversal): drop the file, the chain
+  stops taking new items; delete it to resume.
+
+## The pieces that already exist (what a lead-on-laptop is built from)
+
+| Concern | Where it lives today |
+|---|---|
+| One item per run, chain to next | `scheduler/launch_gate.py::chain_once`, `scheduler/chain_loop.py` |
+| Never two at once | run-lock `scheduler/.chain.lock`; owner-priority `scheduler/.owner_active` (SessionStart hook) |
+| Market-hours deferral | code-building items wait for 15:30 IST; docs/paper items may run in-session (§14.2) |
+| Usage-limit back-off | duty §14.3 (15 min → 2h, say-once, auto-resume) |
+| Observation while it runs | the `/build/` mirror room + `docs/EYES.md`; the Telegram BUILD line; `reports/live_run.log` |
+| Kill / park | `CHAIN_STOP` file; a STOP verdict parks the chain |
+
+So "lead on laptop" is **not a new system** — it is the existing foreground chain, run on this box, watched
+through the mirror. The design question is only how a human keeps it alive across the two things that stop it:
+a usage-limit pause, and a reboot.
+
+## The two gaps, stated honestly
+
+1. **Usage-limit auto-resume is unproven on this box (`G-RESUME-EXEC`, §14.3b).** The one-shot resume task
+   registers but never executes here — Task Scheduler reports it running and holds it. So after a usage-limit
+   pause the operative fallback is the one §14.7 already names: a human ping and a human double-clicking
+   `START_CHAIN.bat`. A lead-on-laptop design must assume **the human is the resume path**, not the scheduler.
+2. **A reboot kills it (by design, §14.7).** There is deliberately no persistence. The design accepts that a
+   reboot ends the run; the human restarts it. The cost of this choice (autonomy can die on a reboot) was
+   taken on purpose, to buy the property that autonomy can always be **stopped** reliably.
+
+## What a build of this item would decide (deferred to the owner)
+
+- Whether to add a **local supervisor the human starts** (not a logon task) that only re-pings the owner when
+  the chain has been idle/paused for N minutes — an alarm, not a resurrector, so §14.7 holds.
+- Whether the mirror's Queue/Now pages are enough for the owner to steer from a phone, or a one-tap
+  "start/stop the chain" control is wanted (start stays a human act; the control just surfaces the .bat).
+- **Reserved to the owner and untouched here:** anything that funds, goes live, or opens a real-money path
+  (§21). This note is about running the *builder*, never the *book*.
+
+## Status
+
+Design note only. No code, no scheduler entry, no change to the standing laws — it records the shape so a
+future build item starts from the constraints already in force rather than re-discovering them.

+"""Weekly live-cost check — the real cost charged per paper trade vs the calibrated backtest cost basis
+(BACKLOG item, owner ruling R-BACKLOG, 2026-09-22). One plain Telegram line, once per ISO week.
+
+The two sides:
+  • LIVE — the real `cost_R` recorded on each paper trade in engine1_rebuild/paper/ledger.csv.
+  • CALIBRATED BASIS — money.cost_readout()['cost_round_trip'] (statutory + 2*half_spread), the same cost the
+    backtest was settled under. While the half-spread is COLD-START (no measured depth yet), that basis IS the
+    conservative fallback, so the delta is ~0 by construction until real fills accumulate — the badge says so.
+
+Badges (§19): COLD-START while the spread is the cited fallback, FILL-LAW-UNVERIFIED until the shadow re-settle
+delta is published (D1). Nothing here touches the trading path; a missing ledger or cost model is a safe no-op.
+"""
+from __future__ import annotations
+
+import csv
+import os
+
+REPO = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
+LEDGER = os.path.join(REPO, "engine1_rebuild", "paper", "ledger.csv")
+LOG = os.path.join(REPO, "reports", "COST-LEDGER.md")
+WEEK_SLOT = os.path.join(REPO, "scheduler", ".cost_week")     # gitignored: last ISO week posted
+
+
+def _rows():
+    try:
+        return list(csv.DictReader(open(LEDGER, encoding="utf-8")))
+    except Exception:
+        return []
+
+
+def _fnum(v):
+    try:
+        return float(v)
+    except (TypeError, ValueError):
+        return None
+
+
+def _basis():
+    """(assumed round-trip cost in R, is_cold_start). The cost model reports COST in fraction-of-capital terms;
+    1R = money.PAPER_R_RUPEES, so cost_R = cost_fraction * NOTIONAL_CAPITAL / PAPER_R_RUPEES."""
+    try:
+        from engine1_rebuild import money
+        ro = money.cost_readout()
+        cost_frac = ro["cost_round_trip"]["value"]                    # fraction of notional, round trip
+        cold = "COLD-START" in (ro["half_spread"].get("source") or "")
+        cost_r = cost_frac * money.NOTIONAL_CAPITAL / money.PAPER_R_RUPEES
+        return round(cost_r, 4), cold
+    except Exception:
+        return None, True
+
+
+def weekly_line():
+    """One plain line comparing the real per-trade cost to the calibrated basis. Honest empty-state when no
+    live round-trips have closed yet."""
+    rows = _rows()
+    costs = [_fnum(r.get("cost_R")) for r in rows]
+    costs = [c for c in costs if c is not None]
+    closed = [r for r in rows if r.get("exit_date") and _fnum(r.get("cost_R")) is not None]
+    basis, cold = _basis()
+    badge = ("[COLD-START]" if cold else "") + "[FILL-LAW-UNVERIFIED]"
+    basis_s = ("%.3fR" % basis) if basis is not None else "n/a"
+    if not costs:
+        return "Cost check: no paper trades carry a cost yet - basis %s. %s" % (basis_s, badge)
+    live_avg = sum(costs) / len(costs)
+    if closed:
+        cl = [_fnum(r.get("cost_R")) for r in closed]
+        live_closed = sum(cl) / len(cl)
+        delta = (" - delta %+.3fR vs basis" % (live_closed - basis)) if basis is not None else ""
+        return "Cost check: %d live round-trips, real cost avg %.3fR vs calibrated %s%s. %s" % (
+            len(closed), live_closed, basis_s, delta, badge)
+    return ("Cost check: %d open positions, entry cost avg %.3fR; basis %s; 0 round-trips closed yet "
+            "- cost-vs-backtest delta lands when trades close. %s") % (len(costs), live_avg, basis_s, badge)
+
+
+def _iso_week():
+    import datetime
+    y, w, _ = datetime.date.today().isocalendar()
+    return "%d-W%02d" % (y, w)
+
+
+def maybe_post(post_fn=None, now_week=None):
+    """Post the weekly line at most once per ISO week. Returns the line if posted, else None."""

+    if last == week:

+        post_fn(line)
+    except Exception:
+        pass
+    try:
+        with open(LOG, "a", encoding="utf-8") as f:
+            f.write("- %s: %s\n" % (week, line))
+    except Exception:
+        pass
+    try:
+        os.makedirs(os.path.dirname(WEEK_SLOT), exist_ok=True)
+        open(WEEK_SLOT, "w", encoding="utf-8").write(week)
+    except Exception:
+        pass
+    return line
+
+
+def tick():
+    """Periodic entry from token_ping's loop; never fatal."""
+    try:
+        return maybe_post()
+    except Exception:
+        return None
+

+    print("cost_ledger demo OK: weekly line built, posts once per ISO week ::", line)
+

+if __name__ == "__main__":
+    _demo()
